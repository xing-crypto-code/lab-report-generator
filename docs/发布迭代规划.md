## 一、现在到底能做什么

核心是一条**本地流水线**，入口是 `python app.py` 起的 Gradio 网页
（`http://127.0.0.1:7860`，`server_name=0.0.0.0` 局域网可访问，`share=False`）。

```
上传指导书(多文件) → OCR/解析 → 检测实验类型
   → 合并 知识库(kb/) 检索片段 → 选模型 → AI 填进老师模板
   → 生成 .docx（保留格式） → 预览 + 下载
   → 生成后可对话修订重新出稿
```

链路目前全通：

| 能力 | 状态 | 位置 |
|---|---|---|
| 多文件指导书解析（PDF/图/Word/Markdown），照片走 EasyOCR | ✅ | modules/parser.py |
| 模板解析 + AI 填充 + 保留格式出 docx | ✅ | modules/filler.py, generator.py |
| 知识库检索注入范文（BM25 + 字符二元组，纯标准库） | ✅ | modules/retrieval.py |
| 多模型（DeepSeek 官方 + 硅基流动 11 款 + 自定义 key/URL） | ✅ | modules/filler.py, config.py |
| 生成后对话修订重出稿 | ✅ | modules/chat.py |
| 历史记录免重新下载 | ✅ | modules/history.py |

**注**：所谓"像 skill"其实是 DeepSeek-Harness 直接读本仓库文件代填数据，
不是仓库独立的对外能力。对外就只是自跑网页。

## 二、关键约束（决定发布形态）

- **依赖重**：`libs/` 1.43 GB（211 包），torch+easyocr 是大头；EasyOCR 模型另 110MB。
- 包安装是 `pip install --target libs`（见 install_deps.py），依赖 **4.x gradio 等 3.14 下的小版本兼容**。
- OCR 保留（产品决策）→ 打 exe 会很大、PyInstaller 配置难。
- 网页分发需服务器 + 域名 + key 策略，成本在云端。

这三点让"三形态"可行性差异很大：
- **exe 双击** → 可行但要面对 1.5~2GB 加打包调试；
- **fork 本地跑** → 最现实，需瘦身使用引导；
- **公开网页** → 花钱，放最后。
