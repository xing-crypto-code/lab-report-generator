# 知识库使用指南

> 目的：让生成的报告越来越像**你们学校、你们老师认可的那种报告**，而不是通用大模型腔。

---

## 一、先理解它到底做了什么

这个知识库**不是训练**，也不改任何模型参数。它在每次生成前做三件事：

```
kb/ 里的文件  →  切块入库（SQLite）  →  按本次指导书检索 3 段最相关片段
                                        →  拼进 system prompt（限 1500 字）
```

所以：

| 你关心的问题 | 答案 |
|---|---|
| 改动什么时候生效？ | 入库之后立刻生效，不用重启 |
| 会占用模型上下文吗？ | 会，最多 1500 字；超了会按句子边界截断 |
| 范例里的数据会被抄进去吗？ | 注入时明确禁止，且要求"每个数字必须来自 OCR 原文" |
| 删掉索引会怎样？ | 什么都没了，但重跑 `ingest` 就能重建 |

**为什么不直接微调？** 微调需要几百条「指导书 → 定稿」配对、要训练要评测，而这个项目
的痛点（章节深度、文风、术语）用检索就能解决 80%。等你攒够定稿，再谈微调不迟。

## 二、怎么放文件（这一步决定了效果上限）

```
kb/
├── 范文/      ← 最重要。老师发的优秀报告、学长的高分作业
├── 指导书/    ← 课程指导书、讲义（补原理与术语）
├── 规范/      ← 写作规范、评分标准、格式要求
├── 草稿/      ← 自己以前的稿子：默认不参与检索，KB_DRAFTS=1 才放行
└── index.sqlite  ← 自动生成，已 gitignore
```

### 三条硬经验

1. **一份文件一个实验**。把一学期的 10 个实验塞进一个 docx，切块会糊成一团，
   检索命中率直接腰斩。
2. **文件名带上实验名**。`霍尔效应实验_模板.docx` 比 `新建文档(3).docx` 好得多——
   文件名会参与类型识别和显示。
3. **先删个人信息再入库**：姓名、学号、老师批注里的评语。范例要能拿去分享。

### 支持格式

| 格式 | 说明 |
|---|---|
| `.docx` | 直接读文档 XML，**不需要** python-docx 也能解析；表格式模板（中文实验报告最常见的那种格子表）会逐格展开，标题不会被并进正文 |
| `.md` / `.txt` | 按 `#` 标题与章节名切块 |
| `.pdf` | 需要 `pymupdf`；**扫描件不行**，要先 OCR（否则只能读出乱码或空） |

## 三、日常操作

```bash
# 1. 增量入库：只处理新增和改动过的文件，几秒钟
python -m modules.retrieval ingest

# 2. 看规模与分布：文档数、块数、字数、按类型/按实验的分布
python -m modules.retrieval stats

# 3. 验证检索：用你真实实验的关键词，看前 3 条是不是你想要的
python -m modules.retrieval search "霍尔效应 螺线管 磁场 测量" -k 3
python -m modules.retrieval search "真值表 与门 输出电平" -k 3 --type "电路/电子实验"
```

只入库某几个文件：`python -m modules.retrieval ingest 范文/某某.docx`
（不会误删库里其他文档——这条有回归测试守着）

彻底重建：`python -m modules.retrieval ingest --rebuild`

如果环境里 `python -m modules.retrieval` 报 `ModuleNotFoundError`（比如依赖没装全），
可以直接按脚本跑：`python modules/retrieval.py ingest`。

## 四、评估：怎么知道它真的变好了

**别凭感觉**。同一个实验，跑两遍对比：

```bash
# A：关掉知识库
set KB_ENABLE=0 && python app.py

# B：打开知识库（默认）
python app.py
```

对比这四项（前三项代码里已有现成信号）：

1. `audit_sections()` 的 AI 腔命中数——日志里会打印（`[filler] 文风自检命中 N 处`）
2. 章节对齐：有没有凭空多出"误差分析""思考题"
3. 章节深度：每节是 2 行敷衍，还是 6~10 行的完整段落
4. 你自己读一遍：像不像同学写的

**什么时候说明库没用？** 如果加上范例后 AI 腔反而变多、或开始抄范例里的数字，
多半是范例质量不齐（混进了低分报告）或片段太长。先 `search` 看看检索出来的到底是什么，
再考虑删掉差的范文。

## 五、可调参数

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `KB_ENABLE` | `1` | 设 `0` 关闭检索注入 |
| `KB_TOP_K` | `3` | 注入几段 |
| `KB_MAX_CHARS` | `1500` | 注入总字数上限 |
| `KB_DRAFTS` | 未设 | 设 `1` 时把 `草稿/` 也纳入检索 |
| `KB_DIR` | `kb/` | 换一个知识库目录（多个课程可各用一套） |
| `KB_INDEX` | `kb/index.sqlite` | 索引文件位置 |

改完 `KB_TOP_K` / `KB_MAX_CHARS` 只影响下次调用，不用重建索引。

## 六、原理（想改代码时看）

- **切块**：以章节标题为边界（`实验目的` `实验步骤` `二、实验数据记录` 都认），
  单块上限 900 字，超长按句号切开。这样检索出来的一段话总是"某章节里的完整内容"。
- **检索**：BM25。中文按**字符二元组**分词（"霍尔效应" → 霍尔/尔效/效应），
  不依赖 jieba；拉丁词与数字（`74LS00`、`2.4V`）整体保留。
  查询用的是一整段 OCR 文本，所以按"词是否出现"计分（qt=1），避免长文本里高频词带偏排序。
- **打分权重**（依次相乘）：

  | 因素 | 系数 | 原因 |
  |---|---|---|
  | 文件身份 | 范文 1.25 / 规范 1.10 / 指导书 1.0 / 草稿 0.55 | 范文最接近目标 |
  | 章节名 | 原理·步骤·数据·误差·讨论 1.15；目的·仪器 0.70 | 要学写法，不是学模板话 |
  | 数字密度 | >22% 时 0.75，>12% 时 0.90 | 纯数据表格式值得学，但数字被照抄风险高 |
  | 模板段落 | `实验目的`/`实验仪器` **直接剔除** | 生成时这两栏本来就照抄指导书原文 |

- **类型过滤**：先按关键词判实验类型，检索时优先同类型片段；写作规范这类全类型通用的文档
  刻意**不打类型标签**，否则会被误判成某一类、把真正相关的范例挤掉。
- **缓存**：索引文件的 mtime 一变就重载，所以入库后下一次生成自动生效。

代码：`modules/retrieval.py`；回归测试：`python tests/test_retrieval.py`。

## 七、常见问题

**Q：入库报"没解析出正文"？**
多半是扫描版 PDF 或纯图片 docx。先 OCR 再入库，或手动复制成 `.md`。

**Q：检索出来的片段很短、断在半句？**
说明原文档那一段本来就很短，或切块阈值把长段落切得太碎。检查 `CHUNK_TARGET`（默认 900）。

**Q：中文乱码？**
读取顺序是 utf-8 → gb18030 → utf-16，一般能兜住；还乱就说明文件本身坏了。

**Q：能放多少个文件？**
纯 SQLite + 内存索引，几百份、几十万字没压力。到了几万块再考虑换向量检索。
