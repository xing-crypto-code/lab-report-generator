# kb/ · 实验报告知识库

放这里的文件会被 `modules/retrieval.py` 切块、建索引，生成报告时自动检索相关片段塞进 prompt。
**目录名决定文件身份**，检索时范文优先、规范次之：

```
kb/
├── 范文/      老师给的优秀报告、学长的高分作业（最值钱，决定"好报告长什么样"）
├── 指导书/    课程实验指导书、讲义（补原理与术语，但注意模型会看一眼怎么表述）
├── 规范/      写作规范、评分标准、格式要求（硬约束）
├── 草稿/      自己以前写的稿子：默认【不参与】检索，KB_DRAFTS=1 才启用
└── index.sqlite   ← 自动生成，已 gitignore，删掉重跑 ingest 即可重建
```

## 为什么单独有一层"草稿"

实测数据（同一门模数电实验课，按正文字数统计）：

| | 同学报告 | 本人稿 |
|---|---|---|
| 实验原理 | 249 字 | 17–24 字（原理基本是图片） |
| 数据记录与分析 | 1645 字 | — |
| 误差分析 | 有 | 多数缺失 |

把薄稿当范文喂进去，模型会学到"实验原理写一句话就行"。所以草稿默认不注入，
确认某份写得够好，再把它移进 `范文/`（或在 `.env` / 命令行设 `KB_DRAFTS=1` 临时放行）。

> 注：文件名里不再带"96 分"之类的成绩——那些数字是本人填进表头的，不是老师给的评分，
> 拿它当质量标签会误导检索权重。

## 公开仓库：个人信息必须清干净

`kb/` 会随仓库公开，所以入库前后都要跑一遍体检：

```bash
python scripts/clean_pii.py scan 周曦睿 邓可          # 只体检
python scripts/clean_pii.py scrub 段黎 --teacher      # 教师名 → 【教师】
python scripts/clean_pii.py scrub 张三 --id 20230001  # 学号 → 【学号】
```

它会把 `document.xml`、页眉页脚、`docProps` 里的作者一并替换，并逐部件复核。
**注意**：图片里的文字（截图上的姓名）查不到，需要人工过一遍——
`scan` 会告诉你每份文件有多少个媒体部件没有做文本审计。

## 支持格式

| 格式 | 说明 |
|---|---|
| `.docx` | 直接读文档 XML，**不需要** python-docx；表格会按 `a \| b \| c` 保留 |
| `.md` / `.txt` | 按标题（`#`）与章节名切块 |
| `.pdf` | 需要 `pymupdf`；扫描件请先 OCR，否则解析不出正文 |

## 用法

```bash
# 1. 把文件丢进对应子目录（文件名随意，但带上实验名更好检索）
# 2. 增量入库（只处理新增/改动过的文件）
python -m modules.retrieval ingest

# 3. 看看库里有什么
python -m modules.retrieval stats

# 4. 验证检索是否靠谱（换成你真实实验的关键词）
python -m modules.retrieval search "霍尔效应 磁场 螺线管 测量" -k 3
```

单独入库某几个文件也可以：`python -m modules.retrieval ingest 范文/xxx.docx`。

## 三条约定

1. **别放敏感数据**：姓名、学号、老师姓名，入库前用 `scripts/clean_pii.py` 清掉。
   （这批文件已替换成 `【姓名】`/`【学号】`/`【教师】`）
2. **一份文件一个实验**：混装多个实验的报告会被切得很碎，检索命中率下降。
3. **范例数据不会被抄**：注入 prompt 时明确写了"范例中的数据一律不得写入本次报告"，
   模型只学写法、详略与章节深度。但入库前还是建议把真实测量数据抹掉——
   这是双保险，也让范例更适合分享。
